# Sports App Backend

## Local setup

Create and activate a virtual environment, then install dependencies:

```powershell
python -m venv flask-env
.\flask-env\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Copy `app/.env.example` to `app/.env` and configure:

```env
SQLALCHEMY_DATABASE_URI=postgresql://USER:PASSWORD@HOST:PORT/DATABASE
JWT_SECRET_KEY=REPLACE_WITH_AT_LEAST_32_RANDOM_BYTES
CORS_ORIGINS=http://localhost:5173
```

`http://localhost:5000` is the backend base URL. `CORS_ORIGINS` contains the
frontend origins allowed to call it. Separate multiple origins with commas. Wildcard
origins are intentionally not enabled.

Generate a JWT secret locally with:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

## Database commands

For a new and empty database, create all tables and stamp the migration version:

```powershell
flask --app app init-db
```

For an existing database, apply committed migrations:

```powershell
flask --app app upgrade-db
```

After changing a SQLAlchemy model, generate and review a migration, then apply it:

```powershell
flask --app app db migrate -m "describe the model change"
flask --app app upgrade-db
```

Never assume an autogenerated migration is safe without reviewing it. `init-db` refuses
to run when application tables already exist.

## Run the API

```powershell
flask --app app run --debug
```

Base URL:

```text
http://localhost:5000
```

## Authentication API

### Sign up

`POST /auth/signup`

```json
{
  "name": "Ana Example",
  "birthdate": "1995-04-20",
  "email": "ana@example.com",
  "password": "a-secure-password"
}
```

`birthdate` must be a real ISO date. The age on signup must be between 18 and
100 years, inclusive. It is stored as a PostgreSQL `DATE`.

### Login

`POST /auth/login`

```json
{
  "email": "ana@example.com",
  "password": "a-secure-password"
}
```

The response contains an access token valid for 15 minutes and a refresh token valid
for 30 days:

```json
{
  "access_token": "...",
  "refresh_token": "...",
  "token_type": "Bearer",
  "access_expires_in": 900
}
```

### Protected requests

Send the access token in the header:

```http
Authorization: Bearer ACCESS_TOKEN
```

`GET /auth/me` is the first protected route and returns the authenticated user.

### Rotate a refresh token

`POST /auth/refresh` must receive the current refresh token in the same Authorization
header. It returns a new access token and a new refresh token. Replace both stored
tokens atomically; the old refresh token must never be used again.

If an old refresh token is reused, the server revokes its persistent session. Every
access or refresh token belonging to that session is rejected and the user must log in
again.

### Logout

`DELETE /auth/logout` accepts either token in the Authorization header and revokes the
whole associated session. A successful logout returns `204 No Content`.

See [docs/api-errors.md](docs/api-errors.md) for the stable error response contract.
